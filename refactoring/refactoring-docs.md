## 세션 1 — 2026-05-30

### Q. 컨트롤러의 책임 분리에 대한 피드백

현재 `cartController.ts`에 다음 세 가지 책임이 몰려 있다고 판단:
1. in-memory DB와 데이터를 읽고 쓴다.
2. DB와 오가는 데이터를 검증한다.
3. 서버 HTTP status를 설정한다.

컨트롤러에는 DB 접근 책임만 남기고, 나머지는 다른 계층으로 분리하려 한다.

### A.

검증 로직을 컨트롤러에서 분리하는 방향은 맞다.  
단, "컨트롤러에 DB 접근 책임을 남긴다"는 부분은 재고 여지가 있다. 서비스 계층을 두면 컨트롤러는 HTTP req/res만 담당하고, DB 접근은 Repository 계층, 검증은 Validator로 분리하는 구조가 일반적이다.

### Q. "컨트롤러의 본래 책임은 HTTP 요청을 받고 응답을 반환하는 것"이라는 건 누가 정한 거냐

### A.

법칙이 아니라 관습이다.  
MVC 패턴에서 파생된 경험적 컨벤션이며, Express 자체도 강제하지 않는다.  
그 관습이 생긴 이유는, 컨트롤러에 책임이 많을수록 테스트가 어려워지고 비즈니스 로직 재사용이 힘들어지는 경험적 문제 때문이다.  
"본래 책임"이라고 단정한 건 틀린 표현이었다.
